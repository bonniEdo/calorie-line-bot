# 四分頁單頁架構

## 結構與資料

- `Index.html` 是唯一頁面外殼，保留打卡表單；全程只有一組可見的底部導覽。
- `SpaRuntime.html` 的 `DietRouter` 管理當前分頁、正在讀取的分頁、元件實例與資料版本。相同讀取合併；過時的導航不能搶回畫面；寫入期間取得的舊資料會重新讀取。
- `getSpaModulesScript_()` 從 History／Personal／Public 的受控原始碼提供靜態元件，使用函式作用域和 Shadow DOM 隔離。資料僅以 JSON 注入隱藏容器，不作為可執行程式。
- `getSpaDataForClient()` 僅接受本人 form 憑證。後續切頁讀取 JSON，不再下載／執行另一份完整 HTML，不複製 Google RPC bridge。
- 新的本人 `view=wall` 入口和原有歷史／設定入口均載入同一外殼。舊 public、group、demo 入口保留相容行為。

## 各功能的保留與同步

| 功能 | 行為 |
|---|---|
| 食物庫、搜尋、餐別、手動輸入 | 保留同一組 DOM 與記憶體狀態；未確認文字不因切頁消失 |
| 拍照、壓縮、辨識、份量編輯 | 請求可在其他分頁繼續；返回保留預覽及待確認結果；隱藏的辨識頁不捲動目前畫面 |
| 飲水、多筆運動、熱量／蛋白質 | 保留原有計算與儲存；設定更新就地同步打卡欄位及摘要 |
| 自動儲存、完成、草稿、重試 | 沿用原寫入流程及憑證檢查；切頁不等於送出或捨棄草稿 |
| 補登、跨日 | 補登先儲存再換日；遲到的讀取不改變目前分頁／捲動；跨日仍使用既有安全重新取得今日資料流程 |
| 趨勢、篩選、清單／月曆、展開明細 | 資料更新維持篩選與已展開筆數；返回保存捲動位置 |
| 週報／月報 | 保留所選報告與隱私開關；產图／分享期間避免背景更新重建報告 |
| 複製歷史餐點 | 先同步目前打卡；詢問後建立今天草稿，仍要選擇還原才替換餐點 |
| BMR、蛋白質活動倍率、提醒、分享偏好 | 儲存前等候打卡同步；設定寫入中暫緩新打卡寫入；成功套用設定後繼續，不重建表單 |
| 未儲存設定 | 背景資料更新保留修改過的欄位；請求發出後再修改的欄位也不被成功回覆覆蓋 |
| 公開牆、連續紀錄、日期、按讚 | 共用路由，保留選擇；樂觀按讚成功／回滾沿用既有流程 |
| 群組牆、打卡空間 | 建立／離開等操作清除群組快取；舊回覆不能重新填入已清除的快取；後端每次群組讀取重新檢查資格 |
| 上一頁／下一頁 | Apps Script 使用 google.script.history；本機預覽使用瀏覽器 history；歷史狀態只存分頁名稱 |

## 更新策略

未修改的分頁保留實例。歷史與牆離開一段時間（30 秒）後返回會背景更新；寫入成功則主動標記相關資料失效。資料正在讀取時再次修改，舊回覆不會被當成最新資料。背景預載等待目前寫入結束，預載失敗不阻止使用者再次點擊。

重新整理、關閉視窗後的餐點恢復仍依原本 localStorage 草稿；記憶體中的篩選、照片和未儲存設定不宣稱跨重新整理保留。伺服器讀寫延遲沒有因 SPA 消失，首次下載靜態元件也會增加初始文件大小。

## 驗證與部署

本機單元測試檢查路由競態、資料版本、失敗重試、模組產生及既有儲存行為。瀏覽器測試使用真實 HTML／CSS／JS、手機尺寸和模擬 Google RPC，檢查主要互動及實際 PNG 下載。

127 版補上延遲回應測試：儲存設定後不得被先前讀取蓋回、群組牆換日期後回公開牆須取得對應日期、權限更新後忽略舊日期回應、群組背景更新保留展開明細，以及待送出的完成指令不被舊自動儲存計時器取消。儲存個人設定也保留尚未建立的空間名稱。

128 版在紀錄牆加入空間入口。建立／加入仍使用主程式持有的 form 憑證；公開或 hub 憑證不能呼叫加入 API。只有 form 認證的牆資料包含擁有者邀請碼；獨立公開牆保留原本權限。空間操作更新主程式的空間清單、分享開關可見性，並使設定與牆資料失效，保留未送出的餐點及未儲存設定。元件 `activate` hook 接收朋友空間導向，單純返回分頁則維持原本選擇與捲動位置。共用邀請與低頻提示邏輯位於 SpaRuntime；獨立 Personal 頁也載入同一份共用程式。

129 版改為建立、新加入或重新加入時預設開啟群組分享，沿用共用開關與歷史紀錄套用規則。LINE 單筆事件與批次成員同步只對「非成員 → 成員」的轉換套用預設，不覆蓋既有成員的關閉選擇。SPA 空間操作先等待打卡儲存，再暫停新寫入；回應同步分享開關後才恢復，避免舊的關閉狀態被自動儲存蓋回。

130 版將邀請文字內的 URL 移出反引號字串，避開 HtmlService 的解析相容性問題。啟動前檢查共用路由、邀請工具與元件是否存在；遇到語法錯誤後不再建立表單或啟動資料讀寫。錯誤頁保留第一個錯誤並隱藏操作列。本機新增危險字串格式檢查與六組瀏覽器啟動失敗情境，但仍須部署到 Apps Script 驗證其 HTML 轉換結果。

131 版在群組頁籤與紀錄牆資料提供正規化 `type`（`line_group`／`space`），舊的無類型群組沿用 LINE 群組。頁籤仍只提供成員有權存取的來源，新增類型不附帶邀請碼或成員名單。朋友卡片合併呈現 LINE 群組與邀請碼空間，LINE 群組的邀請入口展開教學，空間仍由建立者分享邀請碼；加入與權限判斷流程不變。主程式更新空間時保留 LINE 群組，並保留空間來源類型。

132 版的朋友介紹使用原生 details 收合。首次掛載依是否已加入群組／空間決定預設展開；之後不因切頁或背景更新重設。LINE 邀請教學與完成打卡後的介紹入口會展開外層介紹，避免導向不可見內容。加入前的分享範圍說明保留在加入區，日常畫面只顯示分享狀態。

133 版將朋友群組清單改為無卡片文字列，主按鈕直接開啟該組紀錄；原生 details 的「⋯」收納邀請與手動複製文字，沒有可用操作的成員不顯示空選單。各 disclosure 以群組 ID 建立穩定識別，重新渲染或背景更新只還原對應群組的展開狀態。

134 版為照片辨識建立每次請求的狀態與耗時紀錄；處理照片／等候回應的提示計時器在完成、失敗與 hydrate 時清除。SPA 切頁保留辨識，切換紀錄日期則使舊請求失效；遲到回應只記錄 discarded，不改寫新日期的結果或等待提示。後端將格式檢查納入同一個最多 3 次的模型呼叫迴圈，失敗仍保留各次耗時與結果代碼。

135 版維持圖片尺寸與 JPEG 品質，改用 blob URL 解碼並釋放資源。AI 短欄位只用於服務傳輸，回覆在後端還原，SPA 與儲存資料格式不變。手動校正熱量會以目前份量和蛋白質重設基準，避免之後變更份量時套用舊熱量比例；詳細文字與蛋白質標籤同步刷新。

正式發布時必須同步更新 Code、Index、History、Personal、Public、GroupWall 與 SpaRuntime HTML，再建立新的 Apps Script 部署版本。無 Sheet schema 變更。135 版另需同步發布 Worker 的異常處理，以及 GitHub Pages 的窄螢幕排版修正。發布前保留可回復的舊部署版本。

正式環境仍須驗證：LINE iOS／Android 鍵盤與相機、實際 Gemini 辨識、原生分享面板、Google history 與 signed URL 重新整理、群組權限撤銷、兩台裝置同時寫入、跨午夜與過期憑證。模擬測試不代替 Google／LINE 服務驗收，也不提供正式效能倍數。
